# Workflow Frame 本地实施与验证记录

日期：2026-09-11。基线：`9bd8f3b`。本次只修改本地代码，未提交、推送、部署或重建 Docker，未调用收费生成。

## 实施结果

- 工作流支持命名 Frame、从选择建框、空框、标题拖动、八方向调整、自动加入、Alt 拖出、解散和复制。主卡完整进入唯一 Frame 时自动加入；按住 `Alt` 拖动并完全离开原框时解除归属。配置及其输出属于同一逻辑单元。
- 运行入口位于 Frame 左上角；顶部菜单提供各 Frame 和“运行全部”。空框或没有生成配置的框不能运行。不同框可以并行，同框、整图与框、重叠生成步骤由服务端事务互斥，继续使用现有调度容量。
- 单框运行允许引用框外静态输入，拒绝框外生成依赖，不执行框外下游。运行快照、历史名称、下载均保留实际范围和启动时名称。
- 前端按服务端 `nodeRunIds` 选择每个输出的运行来源。可见输出和打开的预览按需加载详情；最多四个详情请求并发。查询失败保留已加载内容；未加载的新来源不能回退到旧图。
- Frame JSON 随现有定义、自动保存、草稿和 Undo/Redo 保存；旧客户端缺少能力标记时不能覆盖已有 Frame。共享展示组件没有 Workflow API/Store 依赖，普通 Canvas 本轮未接入 Frame。

## 复审中修正的问题

1. 重试与调度领取统一先锁 Run、后锁 Output，去除可能造成死锁的反向取锁。
2. 创建与重试不能通过空 Workflow ID 或旧的直接创建入口绕过范围互斥。压测/历史测试夹具独立构造合法历史数据。
3. 409 返回真正被锁定的最新 revision。迁移归一化旧 scope 组合并添加数据库约束，避免不一致范围污染概览。
4. 多范围结果索引每个运行只构建一次；为框外打开的预览保留详情加载。
5. 无 Frame 的旧工作流刷新后仍使用最近一次整图运行提供状态/下载。历史页按账号隔离，旧账号请求不能污染新账号界面。
6. 框名输入隔离拖动，支持输入法、取消与只读切换；空框禁用运行，同名菜单项用 ID 区分，复制遵守 1000 Frame 上限。

### SQL 计划验证

在专用测试数据库的事务临时表中构造 10,000 条运行摘要、30 个范围，使用与生产相同字段顺序的范围索引并执行 `EXPLAIN (ANALYZE, BUFFERS)`；事务最后回滚。原始字段的 `DISTINCT ON / ORDER BY` 使用 Index Scan → Unique，没有 Sort，单次执行 3.906 ms；CASE 表达式对照使用 Seq Scan → Sort → Unique，单次 34.411 ms、排序内存 1838 KiB。这证明此夹具能利用范围索引顺序；它是单次临时表实验，不是生产 SLA 或多次性能统计。

### 浏览器

## 边界与上线注意

- 普通 Canvas 只保留可复用基础组件，本轮未增加包裹框界面或修改其保存文档。
- Frame 与节点一起缩放；极低缩放下标题和角点也会缩小，可以使用顶部范围菜单启动，精细拖动/改名宜放大后操作。
- 真实供应商、真实媒体下载及生产数据库迁移未执行。Go 测试使用专用测试数据库和隔离 schema。
- 后端需先具备迁移与 `frameSchemaVersion` 能力保护，再发布新前端；旧后端无法安全写入 Frame 定义，不可直接回退丢弃新字段。
- 运行表新增范围字段与索引，但不新增 Frame 表，也不修改媒体生命周期规则。停止仍沿用已有“阻止后续提交，已提交任务收尾”的语义。
