# Workflow 本地图片导入

本地拖图、工具栏上传与图片输入卡替换使用同一流程：`image-storage.uploadImage` 先读取并缓存文件，立即显示本地预览；共享 `canvas-local-image-upload-controller` 在后台上传；确认媒体 ID 后通过 `promoteImageStorageKey` 绑定缓存。Workflow 三个入口均使用 `library` 意图，成功图片进入“我的素材”。已有素材选择和视频入口不变。

## 运行与交互

- 每批拖图最多 20 张，按原文件顺序排列，落点在读取开始时固定。共享控制器最多执行 3 个上传，重试和恢复同样排队；被取消但尚未结束的请求仍占用名额。
- 替换保留节点 ID、位置、连接和 Frame；尺寸适配会造成 Frame 重叠时保留原尺寸，等比例包含预览。失败可重试或取消替换。
- 待上传或失败的输入阻止依赖它的运行范围，包括 Frame 引用的框外输入；其他 Frame 不受影响。已经启动的运行继续使用原快照。

## 保存、历史与恢复

`workflow-local-images.ts` 保存操作身份和纯图适配规则；`use-workflow-local-images.ts` 管理预览、上传与恢复。后端仍接收原有 Workflow Definition：新图确认前是空图片输入，替换确认前保留原媒体 ID。

浏览器本地记录按用户、Workflow、节点与操作 ID 隔离。记录包含缓存 Key、文件信息、替换前引用、状态及已确认媒体 ID，不保存 Blob URL、Base64 或签名 URL。文件存储于已有 IndexedDB 图片缓存。恢复需要先取得编辑权并核对 revision；冲突沿用草稿确认，不能自动覆盖远端。全部上传完成且媒体引用保存成功后移除恢复草稿。

历史快照只记录操作 ID，并将上传结果回填归一化；上传进度与完成不增加撤销次数。Undo/Redo 根据操作表解析已确认结果，避免再次上传。旧回调必须同时匹配当前节点和操作身份。

`image-cache-retention.ts` 登记持久缓存引用，供 Canvas 与 Workflow 共用缓存清理检查。当前图、未完成导入和仍可撤销的操作保留本地文件。确认媒体 ID 后发生缓存绑定错误，重试仅绑定缓存，不再次上传。

恢复限于同一浏览器、同一用户且缓存仍存在。缓存丢失会提示重新选择文件。浏览器存储不可用时提示恢复记录无法保存，不承诺跨设备恢复。

## 验证

相关回归覆盖本地读取顺序/数量、实际请求并发、过期回调、替换取消、历史回填、恢复、缓存丢失、清理交错和 Frame 运行限制。浏览器使用模拟上传和工作流接口验证拖图、工具栏、替换、关闭重开、revision 冲突、编辑权、广角及深浅主题；不调用生成接口。
