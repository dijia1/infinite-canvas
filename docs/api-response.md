# 前后端接口响应约定

后端业务接口统一返回 JSON：

```json
{
  "code": 0,
  "data": {},
  "msg": "ok"
}
```

- `code`: 业务状态码，`0` 表示成功，非 `0` 表示失败。
- `data`: 业务数据。失败时通常为 `null`。
- `msg`: 响应消息。成功默认为 `ok`，失败时放错误原因。

前端请求逻辑以 `code` 判断业务是否成功。当前后端业务失败也会返回 HTTP 200，前端不要只依赖 HTTP 状态码判断结果。

接口连接失败、服务不可达、返回体不是约定 JSON 时，前端按网络或接口异常处理。

## JSON 请求体上限

JSON 解码同时限制读取字节数并检查文末，只接受一个 JSON 值。超过请求体上限返回 HTTP 413；语法或结构错误返回 HTTP 400，响应仍使用上述 envelope。原有业务错误的 HTTP 200 约定保持不变。

- 单画布文档仍限制为 4 MiB；创建和保存的请求体额外允许 64 KiB 的字段开销。
- 流程请求保持 4 MiB 加 64 KiB；生成请求和系统设置请求为 1 MiB；素材元数据、分享、角色和目录同步请求为 64 KiB。
- 画布导入每次最多 200 个项目，请求体最多 16 MiB 加 64 KiB。浏览器按最多 200 个、约 8 MiB 拆成顺序批次。每一批仍以事务写入；后一批失败不会回滚已完成批次。使用原项目 ID 重试可继续导入，已有项目不会被覆盖。
- 画布 PUT 的读取超限仍遵守保存回执语义：新请求返回 `canvas_save_rejected`；已存在的请求 ID 返回 `canvas_save_request_mismatch`，不能据此丢弃原未确认请求。

这些限制只针对 JSON。图片 50 MB 和视频 100 MB 的上传上限、OSS 直传与流式转存行为不受影响。
