# Frame 边缘、缩放与自动归属适配（2026-09-12）

## 实现范围

本次在已有 Frame 功能上调整交互，保留原工作区修改。除 Workflow Definition 增加 Frame 重叠校验外，没有修改数据库、运行准入、保存协议或媒体生命周期。

### 八方向边缘操作

四边和四角都可以直接拖动，无需先选中 Frame。尺寸按屏幕像素计算：

| 缩放 | 可见边线 | 边缘操作带 | 角点范围 |
| --- | --- | --- | --- |
| ≤30% | 3px | 28px | 36×36px |
| 30%～100% | 线性插值 | 线性插值 | 线性插值 |
| ≥100% | 2px | 16px | 24×24px |

操作带约 75% 在框外，25% 在框内；极小 Frame 的内部范围受限，保留中心区域。四角优先于本框的边缘，相邻框按真实边界距离选择，同距优先选中框。节点、连线、标题操作按钮、输入框和浮层保留自身事件。

四边只调整对应轴，四角调整两轴。沿用最小 240×160 画布单位、成员包围范围和留白限制。普通调整固定对边，不移动成员；拖动中异步结果扩展了 Frame 时，后续手势保留最新成员和未拖动边界。

### 标题与缩放

背景与操作层分开：背景在节点后方，标题和反馈位于独立操作层。标题仍在框内顶部，通常保持 32px 屏幕高度、12px 文字、24px 按钮。宽度不足时依次隐藏状态、运行文字和标题；极小框的运行入口保留在顶部菜单。

视角应用时同步更新缩放 CSS 变量，静止鼠标的边缘命中也会重新判断。缩放不改写 Frame 的位置、尺寸或成员关系；原有视角同步机制保持不变。可见边线放在反向缩放的操作层中，避免浏览器把高倍缩放时的亚像素边框取整后放大。

### 自动归属与 Alt 拖出

未归属逻辑节点在普通拖动结束或创建后，只有主卡完整进入唯一 Frame 才自动加入；生成结果卡随配置归属，本身不触发加入。成员普通拖动会继续属于原 Frame，并在需要时扩张 Frame。

按住 `Alt` 开始拖动时锁定为移出手势。超过移动阈值后，当前选择整体移动；主卡完全离开原 Frame 的成员解除归属，仍在原 Frame 内的成员恢复归属。Alt 拖出不会直接加入另一个 Frame；跨框移动需要先移出，再普通拖入目标 Frame。一次拖动的位置与成员变化形成一次历史记录。`Shift` 只用于多选，原 `Shift+J`、`Shift+P` 和菜单入口已移除。

Frame 之间不允许严格重叠，边界接触允许。创建、移动、缩放和成员移动引起的扩张共用同一几何约束；服务端保存校验也拒绝重叠定义。移动或调整 Frame 不执行自动归属。

## 文件与耦合

- `web/src/components/canvas-frame.tsx`、`canvas-frame.module.css`：共享外观、反向缩放标题、悬停边线和只读展示。
- `web/src/components/use-canvas-frame-resize.ts`：画布级委托命中、事件优先级和光标；无需为每条边增加透明 DOM 拖动条。
- `web/src/lib/canvas-frame-interaction.ts`、`canvas-frame.ts`：屏幕命中几何、八方向尺寸约束。
- `web/src/features/workflows/workflow-frames.ts`、`use-workflow-frames.ts`：逻辑节点与输出、自动成员关系、防重叠位移、手势历史及异步更新保护。
- `web/src/app/(user)/canvas/hooks/use-canvas-interactions.ts`：共享节点拖拽生命周期、Alt 起始状态、完成与取消事件，不引用 Workflow 或 Frame 类型。
- `web/src/features/workflows/workflow-editor.tsx`：将共享展示和命中接入 Workflow 自身状态与操作。
- `web/src/app/(user)/canvas/components/infinite-canvas.tsx`：同步视角 CSS 变量和局部视角事件，不改图片清晰度策略。

共享组件不依赖 Workflow API；普通 Canvas 后续可复用外观和几何，运行按钮仍由 Workflow 传入。

## 验证

行为测试覆盖：四边和角点、20px 框外命中、缩放插值与两端限制、极小框中心、最小尺寸、固定对边、晚到输出、拖动阈值、Alt 锁定与取消恢复、自动归属、输出跟随、Frame 严格重叠与边界接触、IME/只读和 RAF 手势合并。

浏览器采用本地生产构建与隔离 mock API，不使用用户工作流，不访问真实生成供应商：

- 14% 下，距底边和右边约 20px 直接拖动成功；成员保持原位、对边固定。
- 标题拖动带动配置和输出整体移动，框外输入不移动。
- 5%、14%、30%、100%、200%、500% 的标题约 32px；两端边线分别 3px、2px。深浅主题均检查过同屏效果。
- 在同一点滚轮缩放、鼠标不移动时，过期边缘命中取消，缩回后恢复。
- 运行按钮单独启动 `frame-a` 的模拟 Run，没有开始拖动；这不构成真实供应商生成验收。
- 原 `Shift+J`／`Shift+P` 验证已由自动归属与 `Alt + 拖动`行为测试取代；浏览器端需要按新交互重新验收拖入、移出和一次 Undo/Redo。
- 生产模拟保存 revision 连续从 1 增至 5，移动、两次边缘调整和整组移出均落到服务端 fixture；刷新显示对应已保存版本。

浏览器未逐一人工覆盖所有相邻框/极小框/只读/IME/异步结果组合，这些边界由行为测试覆盖。没有进行真实数据库或收费任务验证。

## 性能记录

实测环境为 Apple M1 Pro / 32GiB，本地生产构建，Codex 内置 Chromium 浏览器，1280×720。使用相同 250 个文本节点和 30 个空 Frame，在 30% 视角、同一屏幕坐标 (650,420) 各滚轮放大/缩小一次。新旧页面的 scene 均为 `translate3d(430px,235px,0) scale(0.3)`。记录每轮输入后约 900ms 内的 rAF 间隔，单位 ms。

| 版本 | 三轮 p50 | 三轮 p95 | 三轮 p99 | 三轮最大值 |
| --- | --- | --- | --- | --- |
| 修改前 | 8.3 / 8.3 / 8.3 | 9.4 / 9.3 / 9.1 | 25.0 / 24.4 / 9.4 | 82.5 / 59.1 / 50.0 |
| 新交互初版 | 9.0 / 8.5 / 9.3 | 41.4 / 57.5 / 58.3 | 92.5 / 91.7 / 108.3 | 92.5 / 91.7 / 108.3 |
| 局部修正后 | 8.3 / 8.3 / 8.3 | 25.0 / 25.0 / 24.3 | 41.0 / 33.3 / 26.0 | 48.9 / 64.9 / 67.0 |

发现初版有冗余热路径后，已跳过相同 viewport 的重复应用与事件、相同命中的重复光标写入，并在纯几何未命中时省略 `elementFromPoint()`。相同双滚轮操作的计数样本：viewport 事件从 4 次降为 2 次，元素查询 7→0 次，光标相关 attribute/class/style 写入 7→0 次。这里的 0 次仅对应鼠标未命中边缘的样本，命中边缘时仍执行遮挡判定和必要的光标更新。最终构建再次验证静止鼠标缩放的 `left → 无命中 → left` 变化。

该 fixture 的 DOM 元素数从 3105 增至 3241（+136，约 4.4%），节点仍为 250、Frame 仍为 30、图片元素为 0。匹配 image/media/workflow-runs 的资源条目均为 1，未增加媒体请求；该数量不等同所有网络请求总数。

**剩余性能风险：**最终短样本的缩放 p95 仍高于修改前，不能宣称性能无回退。标题的反向缩放、宽高更新、容器查询和边线绘制具有新增开销；本轮仅删除了可直接证明的重复工作，没有扩展为渲染架构改造。若需要收紧帧预算，应进一步用长时间 Performance trace 区分 style/layout/paint 成本，再决定是否将 Frame CSS 变量缩小到专用层。

这些为顺序采集的短样本，未随机交错 A/B，也不是持续负载测试。初版三轮采样附近有其他隔离页面检查，可能受干扰；单独补测初版 p95 为 25.1ms、最大 116.4ms，也说明不能仅由三轮数值估算精确倍率。旧构建缓存导致的伪“新版”样本已排除。

尝试采集平移时，工具的左键拖动实际进入框选，没有改变 viewport；这些样本全部排除。当前浏览器工具未提供持续中键拖动或按住空格拖动，因此本轮**没有有效的真实平移 A/B 数据**。手势状态清理有回归测试，但不替代浏览器平移性能验收。

原始有效样本与限制见 [性能数据](workflow-frame-interaction-metrics.json)。测试脚本与完整本机证据保留于 `/tmp/frame-edge-adaptation/`；它们仅可用于隔离 mock 环境。
