# 无限画板视频资源与封面设计

状态：P1/P2 已在本地实施，尚未部署。范围为 P1 共享视频资源管理和 P2 OSS 同步截帧；P3 完整视频本地缓存暂缓。

## 1. 目标与边界

OSS 保存视频本体；Canvas 继续保存 metadata.mediaId，不保存签名地址、Blob 或新 poster 字段。新文件使用新 mediaId，不引入 mediaVersion 数据字段。

降低重复签名请求和未播放视频的加载。共享签名不保证多个原生播放器共用一份视频下载；流量收益需要测量。不同标签页不做跨页请求协调。

不引入 IMM、封面永久文件、视频转码、完整视频 IndexedDB 缓存或新数据库表。封面属于可丢弃的小图片缓存。保留视频原有播放控件及画布滚轮缩放。

## 2. 当前接入位置

- `web/src/app/(user)/canvas/components/canvas-node.tsx`：VideoNodeContent 消费共享资源租约和独立播放组件；节点 memo 比较包含可见状态。
- `web/src/app/(user)/canvas/[id]/canvas-client-page.tsx`：复用 onScreenNodes 和现有视口计算，向视频节点传递真实可见状态；不额外创建一套可见性算法。
- `web/src/app/(user)/canvas/stores/use-canvas-store.ts`：复用 syncScope 的身份边界，并使用独立会话代数防止 A→B→A 的旧请求回写。
- `web/src/services/api/video-media.ts`：沿用媒体 access 接口，补齐 previewUrl 类型、20 秒请求超时和可识别的错误分类。
- `service/media.go`：在已有鉴权后，对视频生成 snapshot previewUrl；图片分支不变。
- `service/image_store.go`：复用 SignedURL(ctx, key, process)，处理参数参与后端签名。

实现时仅新增有实际职责的资源管理器与视频内容组件；复用图片加载队列、资源释放模式，避免改写整套图片缓存。

## 3. 共享资源管理器

位置建议为画布 `media/video-resource-manager.ts`。管理器由用户画布区域的客户端生命周期持有，同一会话跨节点共享；不得在服务端跨用户共享实例。

每个 authScope/project 生命周期创建独立管理器，内部按 mediaId 索引；实例及条目身份用于隔离旧会话结果。snapshot 规则在此版本固定，媒体 ID 不变时封面参数不变；未来增加可选截帧参数时须扩展缓存键。

每个访问条目保存：url、previewUrl、expiresAt、pending 请求、内部 AbortController、消费者集合、最近使用时间和请求代数。封面条目保存 Blob URL、字节数、占用数及失败到期时间。

建议接口：

- acquire(mediaId)：取得租约；注册消费者本身不立即下载视频。
- lease.getAccess()：有效地址直接复用，否则合并并发请求。
- lease.refreshAfterFailure(failedUrl)：若已有更新地址则复用，否则合并同一旧地址触发的刷新。
- lease.getPoster()：通过封面队列读取或生成共享的图片缓存结果。
- lease.release()：幂等释放该消费者。
- resetSession()：取消旧会话请求，清空签名与封面缓存，使旧条目身份失效。
- dispose()：释放全部请求、定时器与 Blob URL。

节点不能直接 abort 共享请求。最后一个消费者离开后进入短暂宽限期；新消费者到来取消回收。资源异步结果核对条目身份和取消信号；播放器另用操作代数阻止已超时或已切换节点的结果回写。

签名按 expiresAt 使用，不固定假设一小时。只在有人请求且接近过期时刷新；无人使用时不设续签轮询。签名更新只更新管理器，不向播放器主动推送 src 替换。

## 4. 初始参数

以下是初始设计默认值，实施时通过常量集中管理，后续根据测量调整，不增加管理员配置项。

| 参数 | 初始值 |
| --- | --- |
| access 请求超时 | 20 秒 |
| 普通 access 临时错误自动重试 | 1 次，间隔 1 秒；取消、无权限、不存在不重试 |
| 签名安全余量 | 60 秒；若有效期不足余量，新返回地址仍可用于本次访问，不循环续签 |
| 最后消费者释放后的请求宽限 | 1 秒 |
| 空闲签名条目保留 | 最多 5 分钟；空闲条目最多 128 个，LRU 淘汰 |
| 封面下载并发 | 4；点击播放获取 access 不排在封面下载后面 |
| 封面请求超时 | 15 秒 |
| 封面缓存 | 当前会话内存缓存，32 MiB / 128 张，达到任一限制淘汰空闲项 |
| 单张封面响应上限 | 2 MiB，流式限制读取，超过则放弃缓存并显示占位 |
| 截帧失败负缓存 | 60 秒；到期后下一次可见加载才重试，不设后台循环 |
| 播放故障自动换源 | 同一故障最多 1 次；换源失败后只能手动重试 |

被播放器或 img 使用中的 Blob URL 不得撤销；全部条目被占用时，不继续突破封面预算，新封面降级为占位。条目数限制约束空闲签名，不因达到上限驱逐正在使用的访问资源。

## 5. 后端封面签名

继续使用 GET /api/v1/media/:id/access，返回现有 url、previewUrl、expiresAt、duration 等字段。签发地址本身不执行 OSS 截帧，浏览器请求 previewUrl 时才处理。

对 OSS 视频，previewUrl 使用固定规则：video/snapshot,t_0,f_jpg,w_480。默认截取第一帧作为封面，不随视频时长改变取帧时间。

截帧规格由后端固定，前端不接受任意 process 或 OSS objectKey。封面权限与视频一致，不需要独立授权或媒体记录。同步截帧仅支持相应编码；MP4 扩展名不能保证编码受支持。

本地存储模式返回空 previewUrl，前端显示占位，不能把视频原地址当图片请求。旧服务返回 previewUrl 与 url 相同或缺少 snapshot 标识时也显示占位。

封面签名失败不应阻断已成功生成的视频访问地址：previewUrl 可为空，记录必要上下文，视频仍可播放。明确权限拒绝或媒体不存在则整个 access 失败并失效对应资源，不能依赖缓存绕过。

沿用现有响应封装，实施时确认业务错误是否有稳定分类；必要时补充媒体访问错误码，不能靠匹配中文错误消息判断权限。保留旧客户端兼容性。

## 6. 封面加载与释放

真实进入视口才获取租约并加载封面，首版不预取视口外视频。封面结果按用户会话、mediaId、snapshotSpec 共享；缓存只存图片，不 fetch 视频本体。

首次通过 access 得到封面和视频地址，但不会因此创建 video 或请求视频本体。取得签名不是下载视频。

封面 fetch 需要 OSS CORS 允许当前站点读取响应。失败、超时、图片解码失败或大小超限均显示视频占位和播放按钮，并进入短期负缓存；不降级为自动创建 video，不无限重试。明确 access 无权限则显示不可访问状态。

同一会话的签名更新不清除已缓存封面；该图片是内容缓存，不是重新请求 OSS 的地址。账户切换、登出、明确媒体删除/权限拒绝会清理它。服务端仍是权限裁决方；浏览器缓存不提供即时跨设备撤权保证。

共享封面 Blob URL 只由管理器创建和回收。消费者释放时先移除 img 引用，再在无消费者且符合回收条件时撤销 URL；异步到达的废弃结果必须释放。

## 7. 播放器状态

封面与播放器分别维护状态，封面请求不能阻塞播放。

封面：idle → loading → ready / unavailable。
播放器：idle → loading → playing / paused → recovering → playing / paused / error。

用户点击后立即获取或复用 access，创建 video。保留 controls、preload=metadata 和画布滚轮行为。异步取得地址后调用 play()，捕获浏览器自动播放限制；被拒绝时保留播放器及播放按钮，不误报网络错误。

每个节点独立持有 activeSrc 和播放状态；共享 manager 只提供资源，不能让同一视频多个节点共享播放进度。

发生网络类媒体错误时，记录 currentTime、播放意图、volume、muted、playbackRate。通过 refreshAfterFailure 获取地址，必要时重载；loadedmetadata 后校正时间至合法范围，完成定位再按原播放意图恢复。

原生 MediaError 不可靠提供 OSS HTTP 状态。MEDIA_ERR_NETWORK 可走一次恢复；明确解码错误直接提示。SRC_NOT_SUPPORTED 不一概视为签名过期，无法判断时提供手动重试。自动恢复预算不会因重渲染或签名刷新重置；只有新的用户播放/手动重试动作开启新尝试。

恢复 access 自身不叠加普通自动重试，避免一次播放器故障触发多轮刷新。loadedmetadata / seek 等恢复等待也设 20 秒上限；取消或用户再次暂停优先于之前保存的播放意图。

## 8. 视口与节点生命周期

- 尚未播放：离开视口释放封面消费者，缓存按预算保留。
- 已播放：离开视口立即暂停，保存进度；短暂离开不立即销毁。
- 在渲染范围内离屏持续 10 秒后允许卸载播放器；若画布原有裁剪更早卸载节点，则先保存运行时播放状态。
- 返回视口不自动恢复声音或播放，显示封面和继续播放入口，用户点击后从保存位置继续。
- 全屏或画中画期间不因画布视口变化暂停或卸载；仍计为活跃消费者。
- 播放状态存放在画布级运行时映射，键为 projectId + nodeId；不写 Canvas JSON。删除节点、切换画布、退出账号时清除。
- 删除一个节点仅释放该节点消费者，不影响同 mediaId 的其他节点。所有节点释放后按宽限期处理无用请求和空闲资源。
- 会话边界同时清除签名、封面、播放状态，已中止请求不得恢复旧画面。

## 9. 分阶段落地

P1：先实现 manager 的并发、会话、释放和超时测试；接入独立视频播放组件，去掉节点各自的签名刷新计时器；验证播放恢复。

P2：增加固定 snapshot 签名及后端测试；接入有界封面缓存和负缓存；复用视口状态，实现点击播放、离屏暂停与状态保留。

P3：不实施完整视频下载或 IndexedDB。后续再依据实测决定是否复用上传 File 做可删除缓存。

## 10. 验收与证据

- 同会话同媒体 3 个节点并发：初次 access 1 次；封面实际下载 1 次；故障刷新也去重。
- 删除 1 个消费者：其余节点正常；释放全部后中止无用请求，计时器和 Blob URL 可回收。
- A→B→A 会话切换：旧请求结果不能回写，前一账号资源不能显示。
- 缓存命中、到期、超时、断网、失败 Promise 释放、负缓存到期、缓存满等定向测试。
- 未点击播放：DOM 中没有该节点 video，网络中没有视频本体请求；封面失败同样成立。
- 点击播放无需等封面；手动播放、暂停、拖动进度、音量、倍速、全屏、画中画、滚轮缩放不回归。
- 普通签名更新不中断播放；网络故障恢复保留状态；第二次恢复失败停止；格式错误无自动刷新。
- 短视频、无时长、黑帧、历史视频、分享副本、OSS CORS 失败和本地存储模式均有降级。
- 深浅主题及 76%、100%、158% 缩放验证封面、占位和控件。
- Bun 定向测试、TypeScript、Go 定向测试、生产构建；浏览器网络与播放交互验证。

以同一测试画布和相同操作对比：access 次数、OSS snapshot 请求数、视频请求数、传输字节、首播时间、自动恢复次数。冷启动与会话缓存命中分别记录。跨域计时数据不可得时使用浏览器网络记录或 OSS 日志，不用签名请求数推算传输字节。

不预先宣称总费用降低：snapshot 有按量处理费用。真实 Bucket 截帧验证可能产生处理费，实施阶段需明确测试样本及授权；不能沿用“未调用收费生成”来暗示截帧免费。

## 11. 发布边界与回退

实现不迁移数据库，不新增 OSS 永久封面，不改变视频本体。回退到原播放器时 Canvas mediaId 仍可使用。前后端分步发布时缺少有效 previewUrl 采用占位，不把视频地址当图片。

本设计不授权提交、部署、重启、重建业务 Docker、修改 Bucket 或调用收费生成/截帧服务。具体 OSS 截帧与 CORS 能力应在实施验收时确认。
